# 已知问题与待办

给接手设计的人：**「已修」一条不要再动，都是踩过坑换来的**；「未修」是需要设计决策的，按优先级排在后面。

## 已修（附原因，别再改回去）

| 位置 | 问题 | 为什么容易踩 |
|---|---|---|
| `format.Line.enhanced` | 判定「是不是逐字行」 | 不能用「标签数 ≥ 字数」——`My ` 这种多字符 token 一个标签盖多个字符；也不能只看 `tag_count`——程序里构造的 Line 没有它。现在：`tag_count > 2` 或 `chars` 与文字等长 |
| `format.parse` | 一行挂多个时间戳 | `[00:01][00:15]副歌` 在商用 LRC 里很常见（复用时），不展开就会把第二段时间戳当成文字 |
| `format.parse` | 译文行的行尾标签 | 译文行是「首+尾共 2 个标签」，逐字行是「字数+1」；只按后者判断会让译文丢行尾，播放器提前切字 |
| `text.lines_with_times` | 双语歌词 | 网易云双语是「原词+译文」共用同一时间戳；不去重会让歌词行数翻倍、ASR 分配全乱 |
| `text.query_from_filename` | 文件名 → 搜索词 | `02 - 好想好想 - 赵薇`、`艾秩曼+-+白狐（TV+Version）` 直接搜搜不到 |
| `sofa.prep_segments` | 切片长度 | 按「下一句行首 + 0.9s」且按字数限长（~0.85s/字）；否则遇到长间奏会把一句摊到几十秒 |
| `audio.decode_stereo` | PyAV packed 格式 | `layout="stereo"` + `format="flt"` 的 `to_ndarray()` 是 `(1, n*ch)` 交错，直接 concat 时长翻倍；必须用 `fltp` |
| `asr._prepare_dll` | ct2 CUDA | 必须把 `torch/lib` 加进 `os.add_dll_directory`，否则找不到 `cublas64_12.dll` |
| `tools/run_sofa.py` | torchaudio 2.11 | 需要 torchcodec 才能 `load`；强制走 SOFA 自带的 librosa 分支 |

## 未修（需要设计）

### 1. 纯音乐 / 无人声的曲子会硬出歌词（优先级高）

现在无论有无主唱都会跑完，产出一份看似正常的 LRC。判断依据可以复用
`audio.rms_envelope` + demucs 的 vocals 轨能量占比：人声轨 RMS 低于某阈值、
或 1–4kHz 能量占比 < 0.08（实测伴奏版 0.05~0.09、真唱 0.21），应直接跳过并报「无主唱」。

### 2. 重复结构 + 剪短音频会错位

`asr.assign_lines` 用行级单调 DP 把歌词行分配到 ASR 分段，**假设行序与音频顺序一致**。
若音频是 TV size / 剪辑版（跳过了某段主歌），DP 会把跳过的行硬塞进相邻段。
可行的解法：先算每行与各分段的覆盖率矩阵，用全局对齐（DTW）后检查「低覆盖率行」并剔除，
而不是强行分配。

### 3. 非中文语言的长音会被压扁

SOFA 只有中文歌声模型；日文/英文走 WhisperX 的 wav2vec2（语音模型），
遇到长拖腔会把时值压短（实测同一句 5.27s 被压成 2.47s）。
可尝试：多语言歌声模型、或在 wav2vec2 结果上做「时长保真」后处理（把过短的音节按能量重新摊）。

### 4. 缺批量与进度

目前只能一首一条命令，长音频全程静默（用户会以为卡住）。
建议加 `kiralrc batch <dir> [--jobs N]`，逐首打印进度/跳过原因，失败不中断。

### 5. 多音字

`text.pinyin_syllables` 用 `pypinyin` 整句转换，比逐字好一些，但歌词里常见的
「了/着/得/还」仍可能取错读音，导致 SOFA 的音素序列偏差。可选：加一个读音白名单或人工覆盖文件。

### 6. 缓存无清理

`work/<歌名>_<hash>/` 会一直增长（每首约 20~50MB）。需要 `kiralrc clean [--days N]`。

### 7. 英文/数字混排

WhisperX 对 `I promise you` 这类片段的字符级对齐粒度是「词」而非「字母」，
渲染成逐字 LRC 时是一串连着的字母同步亮起——不算错，但和中文的逐字观感不一致。
如果要统一，需要按字母均分该词时长。
